# Plan 0: Headless and Hook Spike (Gate) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Confirm or refute every assumption in spec §7.4 (items 1–18) against the real `claude` binary, record the evidence, and apply any resulting spec edits before Plan 2 is written.

**Architecture:** A throwaway vault outside the repo exercises headless `claude -p` runs and interactive sessions driven through tmux. Hooks in the throwaway vault log their stdin JSON and environment to a file so hook inputs can be inspected. Only the results document and spec edits are committed; all spike code is throwaway.

**Tech Stack:** bash, jq, tmux, `claude` CLI (whatever `claude --version` reports; record it).

**Spec:** `docs/superpowers/specs/2026-09-30-vault-template-design.md` (§7.4 is the checklist; §6.3, §6.17, §6.19, §6.20, §7 are what it validates).

## Global Constraints

- Spike files live in `SPIKE="${XDG_CACHE_HOME:-$HOME/.cache}/jarvis-spike"`, never inside the repo.
- Never modify `~/.claude/settings.json` without the explicit consent step in Task 4; always restore it from the backup (a `trap` restores on any exit).
- Use `--model sonnet` for spike runs (permission behaviour does not depend on the model; this bounds cost).
- Record every item as **PASS**, **FAIL** or **PARTIAL** with the exact command and the observed output excerpt. Do not mark PASS without evidence.
- A FAIL is a useful result, not a blocker for this plan: record it and the spec change it requires.

## Review Focus

1. A permission rule that *appears* to work because the model chose not to use a tool. Every denial test must show the tool was actually attempted (tool call visible in `--output-format stream-json` output) and denied.
2. Hook logs that capture only the last invocation: the logger must append, one JSON line per event, with a timestamp.
3. A restored `~/.claude/settings.json` that differs from the original: Task 4 compares checksums after restore.
4. Interactive items run inside a session that was never trusted: the first launch must accept the trust dialog, and the result must note it.
5. Tests run from the wrong working directory: every `claude -p` call uses `cd "$SPIKE/vault"` explicitly.

```bash
#!/bin/bash
set -euo pipefail
SPIKE="${XDG_CACHE_HOME:-$HOME/.cache}/jarvis-spike"
cd "$SPIKE/vault"
cmd="$1"; shift
run_id="${RUN_ID:-spike1}"
mode_flags=(--restricted --settings system/headless.settings.json)
[[ "${MODE:-}" == fallback ]] && mode_flags=(--setting-sources project --settings system/headless.settings.json)
JARVIS_HEADLESS=1 claude -p "/$cmd $run_id" --model sonnet \
  "${mode_flags[@]}" --strict-mcp-config --no-session-persistence \
  --permission-mode dontAsk --output-format stream-json --verbose \
  --tools "Read,Glob,Grep,Edit,Write,Bash" \
  --allowedTools "Edit(/wiki/.staging/$run_id/**)" "Bash(system/scripts/vault_index.py query:*)" "Bash(system/scripts/vault_index.py stage:*)" \
  "$@"
```

- [ ] **Step 5: Create the hook logger and project hooks**

`$SPIKE/hooklog.sh`:
```bash
#!/bin/bash
# Appends one JSON line per hook event: the stdin payload plus selected environment.
LOG="${XDG_CACHE_HOME:-$HOME/.cache}/jarvis-spike/hooks.jsonl"
payload="$(cat)"
jq -cn --arg ts "$(date -Is)" --arg event "${1:-unknown}" --argjson in "$payload" \
  --arg entrypoint "${CLAUDE_CODE_ENTRYPOINT:-}" --arg attended "${CLAUDE_CODE_SESSION_ATTENDED:-}" \
  --arg session "${CLAUDE_CODE_SESSION_ID:-}" --arg headless "${JARVIS_HEADLESS:-}" \
  '{ts:$ts, event:$event, env:{entrypoint:$entrypoint, attended:$attended, session:$session, headless:$headless}, input:$in}' >> "$LOG"
if [[ "${1:-}" == "Stop" && -f "${XDG_CACHE_HOME:-$HOME/.cache}/jarvis-spike/block-once" ]]; then
  rm -f "${XDG_CACHE_HOME:-$HOME/.cache}/jarvis-spike/block-once"
  echo '{"decision":"block","reason":"Reply with exactly: <vault-digest>SPIKE DIGEST</vault-digest> and then stop."}'
fi
if [[ "${1:-}" == "SessionStart" ]]; then
  size="${RECALL_SIZE:-100}"
  ctx="$(head -c "$size" /dev/zero | tr '\0' 'x')"
  jq -cn --arg c "RECALL-MARKER $ctx" '{hookSpecificOutput:{hookEventName:"SessionStart", additionalContext:$c}}'
fi
exit 0
```
