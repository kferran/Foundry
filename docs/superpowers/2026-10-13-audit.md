# Audit: security and correctness of the template

**Date:** 2026-10-13
**Baseline:** `master` at 9d8a1fa (after the express install, the focus deletion, Slack notices, inbox triage, RCA and the fast lane merged).
**Method:** two read-only passes over the code, one against the threat model in `FOUNDRY.md` Security model, one over the core run paths; the gate (`verify_setup.sh`) run in a container with `bats` 1.14 and `pytest` 9.1; the findings marked **verified** were re-read in the code by the author of this document, the rest are the auditors' reading and should be re-checked by whoever fixes them.
**Companion:** `2026-10-11-simplification-review.md` covers size and shape; this audit covers whether the system holds its promises.

## 1. Verdict

The security model holds where it was designed: the publish gate refuses every traversal tried, the connector fetches are confined to one tool and checked afterwards, Work Order delivery pushes one validated ref from a bare repository, the hooks quote everything. The gaps are at the edges the model did not name: the daily unattended merge of the template runs merged code with the user's credentials, two gate rules are enforced only by prompt text (`type: index` skips the partition wall; ingest may write `Now.md` and preferences), and the deny lists for headless runs and Work Order sessions are thinner than the ones the Nightshift already carries.

On correctness the core is careful (ledger trap, journaled publish, idempotent apply, once-a-day alerts). The defects found are races and budget mismatches on real-world paths: concurrent `stage` calls, a partial publish counted as a failed attempt, the brief's unit timeout under its own worst case, the daily update that can never run on a standalone machine, and a Now tick stamped late.

## 3. Security findings

| # | Sev. | Where | Finding | Fix |
|---|---|---|---|---|
| S1 | High | `update_template.sh` (unattended path), `vault_sync.sh` merge | **Verified.** The daily update fetches the template's default branch, merges it unsigned, then runs scripts from the merged tree (`commit_runs.py`, `vault_index.py rebuild`, `install_units.sh --update`, which re-renders and reloads systemd units). Every later timer runs the merged code as the user: `vault_sync.sh` with push credentials, `nightshift.py` with `gh`. The merge also carries `.claude/settings.json`, the headless prompts and `system/hooks/*.sh`, which run in every interactive session. `vault_sync.sh` merges `origin/<branch>` the same way, so a compromised client owns the server | Merge only a tag verified with `git verify-tag` against a pinned key; run the post-merge steps from the pre-merge checkout; or keep the unattended update opt-in (the express install already made it opt-in for new vaults) |
| S2 | Medium | `publish.py` `_walls`; `system/schemas/index.md` | **Verified.** `_walls` returns early when the staged note's `type` is `index`, and the index schema's `folders` is all of `wiki/`. A poisoned `personal` digest can have ingest stage `wiki/personal/concepts/X.md` with `type: index` and `[[WorkNote]]` links; schema passes, the wall is skipped, the note publishes | Pin the index schema to `wiki/Index.md` and reject `type: index` under `wiki/<partition>/` in `_check` |
| S3 | Medium | `nightshift_run.py` `_deny` | A Work Order session is denied `wiki`, `raw`, `briefings`, `system/logs`, and not `system/index.db` (every note body, all partitions), `.git` (every note's history), `system/quarantine`, `~/.claude/projects/` (Foreman transcripts) or `~/.gitconfig`. A prompt-injected codebase can read and commit them to `order/<id>`, which the runner pushes and opens as a PR | Deny the vault root and `~/.claude` wholesale in the session profile; allow only the clone |
| S4 | Medium | `system/headless.settings.json` | **Verified.** No `sandbox.filesystem.denyRead`; Read denies miss `~/.config/foundry/**` (Sentry token), `~/.config/gh/**`, `~/.azure`, `~/.aws`, `~/.netrc`, `~/.git-credentials`, `~/.claude/projects/**`. Read containment rests on `blockReadsOutsideWorkingDirectories`; Bash containment on five `vault_index.py` prefixes in `run_headless.sh` | Copy the Nightshift `denyRead` list into the headless settings and add the missing Read denies |
| S5 | Medium | `run_headless.sh` ingest targets; `publish.py` `_check` | **Verified.** Ingest's publishable targets are `wiki/<partition>/**`, and `_check` refuses only `meetings/` for ingest. The prompt rule "never stage Now.md" in `ingest.md` is unenforced: a poisoned digest can patch `Now.md` within the shrink guard (fake owed lines every recall and brief then carry) and create `preferences/` notes that steer later sessions | Reject `Now.md` for ingest in `_check` as meetings are; consider limiting `preferences/` to `patch` decisions |
| S6 | Medium | `.gitignore`, `vault_sync.sh` `git add -A`, `.githooks/pre-commit` | A dropped meeting transcript is committed and pushed to `origin` before the server imports it; the hook runs `redact.py --kinds` (named detectors only), and the pushed blob stays in history after the import deletes the file | Keep drops gitignored and move them server-side, or rewrite the drop through full `redact()` in the hook |
| S7 | Medium | `nightshift_run.py` session start; `nightshift_session.py` | The session inherits the full environment: `SSH_AUTH_SOCK`, `GH_TOKEN`/`GITHUB_TOKEN`, `DBUS_SESSION_BUS_ADDRESS` survive the file denies. With the git host in `order_hosts`, a prompt-injected session can push itself; the contract asks it not to, and the containment check compares local refs only | Pass a scrubbed environment; extend the self-test with `git ls-remote` against an allowed host |
| S8 | Low | `vaultlib/redact.py` | `ASSIGNMENT` uses `\b` before the key, so `client_secret=`, `access_token=`, `refresh_token=` and `AWS_SECRET_ACCESS_KEY=` pass in digests and inbox copies; hex-only strings never reach the entropy threshold, so 32-hex keys survive; `Authorization: Basic` and emails are not redacted | `(?<![A-Za-z0-9])` in place of `\b`; run the credential patterns inside `redact()`; add a hex-length detector |
| S9 | Low | `nightshift_deliver.py` stale claims | A research note's `## Stale claims` bullets (model-written from web pages) become a `session_digest` in `raw/<p>/notes/` that ingest treats as corrections to existing notes | Surface stale claims in the Work Order report for the owner instead of queuing them |
| S10 | Low | headless Read scope | A `personal` ingest session may read `raw/work/**`, `wiki/work/**` and `system/logs/runs/*/claude.json`; the wall check is link-based, so copied text passes. Documented as a design limit | A per-run settings file with Read denies for the other partition and `system/logs/**` |

## 5. What holds up

- **Publish gate paths:** `safe_rel` rejects `..`, absolute, backslash and dot segments; `target_matches` is prefix-exact; symlinked files and directories in staging are refused; existing notes must be staged through `record_stage`; protected fields, provenance, headings, the 60% body guard, the mtime and sha conflict checks, the journaled rename with recovery. No traversal was constructed.
- **Connector fetches:** one allowed tool, a deny list built from every user allow rule that fails closed on a broad rule, hooks off, a fresh `/tmp` cwd, every session's `tool_use` blocks checked afterwards (exit 7 on any other tool), output taken from `structuredContent`, interpolations regex-validated.
- **Work Order delivery:** pushes only `sha:refs/heads/order/<id>` with a validated id from a bare runner repository filled by `upload-pack`, `core.hooksPath=/dev/null`, protected-path proposals plumbing-committed and size-capped, verify in `bwrap` with `/` read-only and no network.
- **Hooks:** every expansion quoted, session ids regex-checked, transcript text only through `jq --arg`, awk or printf, no `eval`.
- **`run_headless.sh`:** the ledger trap captures `$?` first, maps signal exits, terminates a torn last line, closes fd 9 for the `claude` tree; cap and attempt counts exclude 2, 3, 4, 6 and signals consistently with `intake.py`.
- **`vault_sync.sh`:** never resolves a conflict, force-pushes a pending branch on a server only, alerts once a day per failure kind, aborts a merge on TERM, bounded network calls, stale `index.lock` detection by process cwd.
- **Secrets:** the Sentry token is read from `~/.config/foundry` with a 0600 check; `az` and `gh` are invoked by argv; `kusto` refuses management commands; `guard.run_query` is read-only with an authorizer.
