# Plan 8c: Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A server and its clients share one vault through a private `origin`: the server syncs on a timer and around every run, conflicts block runs until a person resolves them, client notes in the briefing reach the server without the briefing being rewritten, and conflict markers never land.

**Architecture:**
- `.githooks/pre-commit` rejects any staged file holding a conflict block (every role).
- `intake.py` extracts each new `#wiki-ingest` block by hash and leaves the briefing as it is (every role).
- `vault_sync.sh` (bash): preconditions, `run.lock`, then `commit_runs.py` → scripted `sync(<role>)` commit → fetch → merge → push, with a deadline, once-a-day failure alerts, and on a conflict an abort, a `jarvis/<role>-pending` branch and a `sync-blocked` marker that pauses the runs.
- A server gets `jarvis-sync.{service,timer}` and one drop-in per run service (`--pre`, the service's prep, `--post`); `install_units.sh` owns drop-ins like units.
- `/backup` in `private` syncs through `vault_sync.sh`; `/setup` gives a client the Obsidian Git settings; health, lint and the README follow.

**Tech Stack:** bash 5, git, flock, jq ≥ 1.6, Python 3.11+ (stdlib), systemd user units, bats ≥ 1.8, pytest.

**Spec:** `docs/superpowers/specs/2026-10-03-two-machines-design.md` §5, the sync parts of §3.2 and §3.5, §7, §8 (8c), §8.1 (8c) and §9 (rev 3, approved).

## Global Constraints

- **Exit codes (spec §5.1):** 0 synced or nothing to do; 1 failure (alerted); 2 usage; 3 blocked; 4 lock busy. `--pre`: marker or unfinished operation first → 3; busy lock and every exit-1 failure → 0. `--post`: always 0.
- **Git environment (spec §5.1):** `GIT_TERMINAL_PROMPT=0`; `GIT_SSH_COMMAND` defaults to `ssh -o BatchMode=yes -o ConnectTimeout=15`; network calls under `timeout`, the smaller of 120 s and what is left of `SYNC_DEADLINE` (default 300 s).
- **Conflicts (spec §5.4):** never resolved automatically; `git push --force origin HEAD:refs/heads/jarvis/<role>-pending`; the marker clears on any cycle that completes the push step, which also deletes the pending branch, alerts "sync unblocked" and starts a skipped brief or debrief.
- **Markers (spec §5.5):** a staged file with a `^<<<<<<< ` line and a later `^>>>>>>> ` line is rejected; `=======` is never looked at; no `git diff --check`.
- **Extraction (spec §5.6):** one drop per new `(briefing, sha256 of the trimmed block)`; records in `system/logs/extracted_blocks.jsonl`, written inside `run.lock`; the briefing is never modified; the 60-second rule stays.
- **Template rule:** no hostname, user path or remote URL is committed. Docs use `<server>` and `<private origin>`.
- **Tool floor:** jq 1.6, bats 1.8, SQLite 3.40, Python 3.11 (no bats `run -N`). Tests use a local bare repo with `GIT_ALLOW_PROTOCOL=file`, a temporary `HOME`, and their own git identity; `systemctl` is always a stub.
- **bats ruling R1:** no mid-test `!`, no `&&` assertion chains, no wall-clock timing assertions. Bats files mode 644; `vault_sync.sh` and `stub_git` 755 (the patches set them).
- **Gate:** `system/scripts/verify_setup.sh > system/logs/gate.log 2>&1; echo "exit=$?"`, then `sed -n '/===== summary/,$p' system/logs/gate.log` (16 suites after Task 3). **Lint:** `system/scripts/lint_vault.sh > system/logs/lint.log 2>&1; echo "lint exit=$?"; tail -n 1 system/logs/lint.log`. Read verdicts from exit codes, never through a pipe.
- **Patches:** every test and implementation step is an exact patch tested in a scratch clone. Save the block to a file in the plan workspace and run `git apply --check <file> && git apply <file>`. A patch that does not apply means the tree differs from the plan's base: stop and compare.
- **Never** install units, run `/setup`, `install_units.sh` or `install_hooks.sh` against the real user session from the template clone; live acceptance uses throwaway clones and calls the scripts directly.
- American English. Branch `feat/plan-8c` from `master` at 2f3c76f (PR #10 merged). Commit trailers name the authoring model.

## Decisions made while planning

- **D1 Order.** The hook (Task 1) and extraction (Task 2) apply to every role and depend on nothing in sync, so they come first and work on their own; the sync core, conflicts, units and docs follow.
- **D2 An unfinished operation before the lock.** The spec checks precondition 4 before the lock (check only) and again after it (marker and alert). Combined: when the lock is busy, exit 3 and write nothing (a sync holding it may be mid-merge); when it is free, take it and write the marker and one alert. Without this, a real stale state would skip every run with no alert. `--pre` never writes.
- **D3 Stale `index.lock`.** Older than 10 minutes and no `git` process whose working directory is inside the vault (read from `/proc`). A `git -C <vault>` started elsewhere is not seen, so the lock reads as stale and the sync blocks: the safe direction, and the lock is never deleted.
- **D4 Timeouts.** In the drop-in, so only a server changes: intake 105 min, brief 45 min (Plan 8d's 30 plus 15), debrief 35 min; `jarvis-sync.service` 10 min. Two sync deadlines (2 × 5 min) plus 5 min margin. Standalone keeps Plan 8d's values.
- **D5 Alerts and state.** Tag `[sync]`. `system/logs/sync-state.json` is one object `{kind, first_seen, last_alerted}`; a different failure kind replaces it. Kinds: `config` (preconditions 1–3), `commit`, `fetch`, `merge`, `push`. Configuration failures alert too, so a misconfigured server timer is visible in the brief.
- **D6 `sync(<role>)` body.** `<path> +a/-r` for a change, `(new)`, `(deleted)`, `(binary)` for a binary change; renames off (a rename is a deletion and a new file); control characters in paths become spaces.
- **D7 Push retry.** Any failed first push re-runs fetch, merge and push once; a second failure alerts.
- **D8 Deleting the pending branch.** `ls-remote --heads` first, then delete. A local bare repo accepts deleting a missing ref with a warning (probed); a hosted remote may refuse.
- **D9 Missed runs.** Server only. A command is started when its configured time (`HH:MM`, config timezone) has passed today and the run ledger has no line for it started today, whatever its exit.
- **D10 Extraction details.** Complete blocks before a nested or unterminated start marker are extracted (safe now that nothing is rewritten); an empty block makes no drop; the bad marker is alerted once per `(briefing, reason, day)`.
- **D11 `--pre` on a client** is unreachable (a client has no units); `/backup` runs the default mode on every role.
- **D12 The client `raw/inbox` warning** lives in `lint_vault.sh`, guarded by the directory existing (under `pipefail`, `find` on a missing directory would fail the hook on every client; the sync suite found this while planning).
- **D13 Probed while planning (2026-10-04):**
  - `systemd-analyze --user verify <unit>` loads drop-ins from `<unit>.d/` beside it and checks that each command is executable, so the installer verifies units with their drop-ins in place.
  - A refused merge (an untracked file in the way) exits 1 with no `MERGE_HEAD`; a conflicted merge exits 1 with `MERGE_HEAD` and unmerged entries.
  - `MERGE_HEAD` is not written while a merge driver runs, so the TERM test uses a `git` wrapper (`system/tests/stub_git`) that signals the script right after a conflicting merge; bash runs the trap before the next command.
- **D14 Merge commits** carry the trailers in a second `-m` paragraph: `sync(<role>): merge origin/<branch>`, then `Jarvis-Command: sync` and `Jarvis-Role: <role>`.
- **D15 Scratch result:** gate 16/16 on the Debian host with all twelve patches applied; every red step's failures checked by checking out its commit.

## Review Focus

1. **A run service's `--pre` exits 3 under real systemd.** Expected: the run is skipped, the unit shows failed, and the next timer fires as usual. Pinned by live acceptance Step 3 (the pre-step's exit) and `sync.bats` "a conflict aborts the merge…" (`--pre` → 3).
2. **An ssh `origin` whose key needs a passphrase or is missing.** Expected: `BatchMode` fails within `ConnectTimeout`, exit 1, one alert a day, runs continue. Pinned by `sync.bats` "an unreachable origin is alerted once a day…" (the alert path) and live acceptance Step 4.
3. **Obsidian Git and a client's `/backup` touch git at the same time.** Expected: one fails on git's `index.lock` (exit 1, alerted), the next attempt succeeds. Pinned by `sync.bats` "a commit the hook refuses…" (the commit-failure path unstages and exits 1).
4. **The sync timer fires while a brief holds `run.lock`.** Expected: exit 4, no alert, the next tick syncs. Pinned by `sync.bats` "a busy run.lock exits 4…".
5. **A half-typed block in a briefing pulled from a client.** Expected: nothing extracted for 60 seconds after the pull (the checkout sets the file's time), and each complete block once. Pinned by `test_fresh_briefing_skipped_and_never_created` and `test_a_known_block_is_not_extracted_again`.

+#!/bin/bash
+# Sync the vault with its private origin: commit, fetch, merge, push (two-machine spec §5.1).
+# Usage: vault_sync.sh [--pre | --post]. Exit 0 synced or nothing to do; 1 failure (alerted); 2 usage;
+# 3 blocked; 4 run.lock busy. --pre exits 3 when blocked and 0 otherwise; --post always exits 0.
+set -uo pipefail  # no -e: every step's failure is handled where it happens
+VAULT_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd -P)"
+cd "$VAULT_ROOT"
+# shellcheck source=lib_config.sh
+source system/scripts/lib_config.sh
+# shellcheck source=lib_git.sh
+source system/scripts/lib_git.sh
+
+mode=default
+(( $# <= 1 )) || { echo "usage: vault_sync.sh [--pre | --post]" >&2; exit 2; }
+case "${1:-}" in
+  "") ;;
+  --pre) mode=pre ;;
+  --post) mode=post ;;
+  *) echo "usage: vault_sync.sh [--pre | --post]" >&2; exit 2 ;;
+esac
+
+export GIT_TERMINAL_PROMPT=0
+[[ -n "${GIT_SSH_COMMAND:-}" ]] || export GIT_SSH_COMMAND="ssh -o BatchMode=yes -o ConnectTimeout=15"
+TZ="$(config_get timezone UTC)"
+export TZ
+role="$(config_get machine_role standalone)"
+LOGS=system/logs BLOCKED=system/logs/sync-blocked STATE=system/logs/sync-state.json
+DEADLINE=$(( $(date +%s) + ${SYNC_DEADLINE:-300} ))
+mkdir -p "$LOGS"
+
+alert() { printf -- '- %s [sync] %s\n' "$(date +%H:%M:%S)" "$1" >> "$LOGS/alerts_$(date +%F).md"; }
+
+# finish <code>: exit, mapped by mode (§5.1 Modes).
+finish() {
+  local rc="$1"
+  if [[ "$mode" == pre ]] && (( rc != 3 )); then rc=0; fi
+  [[ "$mode" != post ]] || rc=0
+  exit "$rc"
+}
+
+# fail <kind> <reason>: alert once a day per failure kind while it persists (§5.3), then exit 1.
+fail() {
+  local first="" last=""
+  if [[ -f "$STATE" ]]; then
+    first="$(jq -r --arg k "$1" 'select(.kind == $k) | .first_seen // empty' "$STATE" 2>/dev/null)"
+    last="$(jq -r --arg k "$1" 'select(.kind == $k) | .last_alerted // empty' "$STATE" 2>/dev/null)"
+  fi
+  [[ "$last" == "$(date +%F)" ]] || alert "sync failed ($1): $2"
+  jq -cn --arg k "$1" --arg f "${first:-$(date -Iseconds)}" --arg l "$(date +%F)" \
+    '{kind: $k, first_seen: $f, last_alerted: $l}' > "$STATE.tmp" && mv -f "$STATE.tmp" "$STATE"
+  echo "vault_sync: $2" >&2
+  finish 1
+}
+
+# net <git args…>: a network git call bounded by the smaller of 120 s and the time left.
+net() {
+  local left=$(( DEADLINE - $(date +%s) ))
+  (( left > 0 )) || return 124
+  (( left <= 120 )) || left=120
+  timeout "$left" git "$@"
+}
+
+git_dir="$(git rev-parse --git-dir 2>/dev/null)" || { echo "vault_sync: not a git repository" >&2; finish 1; }
+
+# in_progress: print why git is mid-operation (precondition 4), or return 1.
+in_progress() {
+  local p
+  if [[ -e "$git_dir/MERGE_HEAD" || -d "$git_dir/rebase-merge" || -d "$git_dir/rebase-apply" \
+        || -e "$git_dir/CHERRY_PICK_HEAD" || -n "$(git ls-files -u 2>/dev/null)" ]]; then
+    echo "operation in progress"
+    return 0
+  fi
+  if [[ -e "$git_dir/index.lock" && -n "$(find "$git_dir/index.lock" -mmin +10 2>/dev/null)" ]]; then
+    # ponytail: a git started elsewhere with -C is not seen; the lock then reads as stale and blocks (safe).
+    for p in $(pgrep -x git 2>/dev/null); do
+      [[ "$(readlink "/proc/$p/cwd" 2>/dev/null)" == "$VAULT_ROOT"* ]] && return 1
+    done
+    echo "stale index.lock"
+    return 0
+  fi
+  return 1
+}
+
+# block <reason>: write the marker (one alert per blocked period) and exit 3.
+block() {
+  [[ -e "$BLOCKED" ]] || alert "sync blocked: $1; intake, brief and debrief are skipped until it is resolved"
+  printf 'reason: %s\ntime: %s\n%s' "$1" "$(date -Iseconds)" "${2:-}" > "$BLOCKED"
+  echo "vault_sync: blocked: $1" >&2
+  finish 3
+}
+
+on_signal() {
+  [[ ! -e "$git_dir/MERGE_HEAD" ]] || git merge --abort 2>/dev/null
+  exit "$1"
+}
+trap 'on_signal 143' TERM
+trap 'on_signal 130' INT
+
+if [[ "$mode" == pre ]]; then
+  [[ ! -e "$BLOCKED" ]] || exit 3
+  in_progress > /dev/null && exit 3
+fi
+
+remote_mode="$(config_get remote_mode none)"
+[[ "$remote_mode" == private ]] || fail config "remote_mode is $remote_mode, not private"
+origin="$(git remote get-url origin 2>/dev/null)" || fail config "no origin remote; run /setup phase 4"
+template="$(head -n 1 system/template_source 2>/dev/null || true)"
+if [[ -n "$template" ]] && git_url_same "$origin" "$template"; then fail config "origin is the template repository"; fi
+upstream="$(git rev-parse --abbrev-ref --symbolic-full-name '@{u}' 2>/dev/null)" || fail config "no upstream; run /setup phase 4"
+[[ "$upstream" == origin/* ]] || fail config "the upstream $upstream is not on origin"
+branch="${upstream#origin/}"
+
+exec 9> system/run.lock
+if reason="$(in_progress)"; then
+  # Unfinished before the lock: a sync holding the lock may be mid-merge, so only a free lock writes the marker.
+  flock -n 9 && block "$reason"
+  finish 3
+fi
+flock -n 9 || finish 4
+reason="$(in_progress)" && block "$reason"
+
+# sync_message: the scripted message for the staged changes (§4.1).
+sync_message() {
+  local a r p st n=0 body=""
+  declare -A num=()
+  while IFS=$'\t' read -r -d '' a r p; do
+    if [[ "$a" == - ]]; then num[$p]="(binary)"; else num[$p]="+$a/-$r"; fi
+  done < <(git diff --cached --numstat -z --no-renames)
+  while IFS= read -r -d '' st && IFS= read -r -d '' p; do
+    n=$(( n + 1 ))
+    case "$st" in
+      A) body+="${p//[$'\n\r\t']/ } (new)"$'\n' ;;
+      D) body+="${p//[$'\n\r\t']/ } (deleted)"$'\n' ;;
+      *) body+="${p//[$'\n\r\t']/ } ${num[$p]:-}"$'\n' ;;
+    esac
+  done < <(git diff --cached --name-status -z --no-renames)
+  printf 'sync(%s): %d file(s)\n\n%s\nJarvis-Command: sync\nJarvis-Role: %s\n' "$role" "$n" "$body" "$role"
+}
+
+# Cycle (§5.1).
+system/scripts/commit_runs.py > /dev/null || fail commit "commit_runs.py could not commit a run (see its alert)"
+git add -A || fail commit "git add -A failed"
+if ! git diff --cached --quiet; then
+  if ! err="$(sync_message | git commit -q -F - 2>&1)"; then
+    git reset -q
+    fail commit "the sync commit was refused: $(head -n 1 <<< "$err")"
+  fi
+fi
+for attempt in 1 2; do
+  net fetch -q origin || fail fetch "git fetch origin failed"
+  if ! git merge-base --is-ancestor "origin/$branch" HEAD; then
+    if ! err="$(git merge -q --no-edit -m "sync($role): merge origin/$branch" \
+                  -m "Jarvis-Command: sync"$'\n'"Jarvis-Role: $role" "origin/$branch" 2>&1)"; then
+      if [[ -n "$(git ls-files -u)" ]]; then
+        git merge --abort
+        fail merge "merge conflict with origin/$branch"
+      fi
+      [[ ! -e "$git_dir/MERGE_HEAD" ]] || git merge --abort
+      fail merge "git merge origin/$branch was refused: $(head -n 1 <<< "$err")"
+    fi
+  fi
+  net push -q origin "HEAD:refs/heads/$branch" && break
+  (( attempt == 1 )) || fail push "git push origin was rejected twice"
+done
+if [[ -f "$STATE" ]]; then
+  alert "sync recovered (was failing: $(jq -r '.kind // "unknown"' "$STATE" 2>/dev/null))"
+  rm -f "$STATE"
+fi
+finish 0
