# Fast Lane Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `FOUNDRY.md` and the roadmap define the fix lane, so a one-sentence fix ships with a failing test and a pull request and nothing else.

**Architecture:** Documentation only: one paragraph in `FOUNDRY.md` Development, one sentence in the roadmap's process paragraph, pinned by `commands.bats`.

**Tech Stack:** Markdown, bats.

**Spec:** `docs/superpowers/specs/2026-10-11-fast-lane-design.md`

## Global Constraints

- Work on branch `docs/fast-lane`. Commit there; do not push or open a pull request.
- Run the suites from the repository root with `TMPDIR=$PWD/.scratch/tmp GIT_CEILING_DIRECTORIES=$PWD/.scratch` (`mkdir -p .scratch/tmp` once). The gate is `system/scripts/verify_setup.sh`.
- Bound tools: bats (`commands.bats`) and the gate.
- Commits use `git commit -F .scratch/<file>`.
- Edits below are described by place and content; the implementer anchors them in the current file text.

## Review Focus

- The four fix criteria in `FOUNDRY.md` match spec §2 word for word: clear from one sentence; no schema, settings file, unit template or headless command text; one failing test; the gate green.
- The promotion rule says the default when in doubt is the feature lane.
- The roadmap's "Next, in order of value" paragraph is unchanged apart from the one added sentence.

### Task 1: The lanes in FOUNDRY.md and the roadmap

**Files:**
- Modify: `FOUNDRY.md` (Development), `docs/superpowers/roadmap.md` (the process paragraph after the table)
- Test: `system/tests/commands.bats`

**Interfaces:**
- Produces: a paragraph "Two lanes" in Development; a sentence in the roadmap naming the fast lane.

- [ ] **Step 1: Write the test**

Add to `system/tests/commands.bats`, after the test that checks the Development section (or at the end of the file when none does):

```bash
@test "FOUNDRY.md defines the fix lane and the roadmap names it (fast lane spec §3)" {
  grep -qF 'clear from one sentence' FOUNDRY.md
  grep -qF 'no schema, no settings file, no unit template and no headless command text' FOUNDRY.md
  grep -qF 'one failing test that passes after the change' FOUNDRY.md
  grep -qF 'the default when in doubt is the feature lane' FOUNDRY.md
  grep -qF 'skips the grill, the spec and the plan' docs/superpowers/roadmap.md
}
```

- [ ] **Step 2: Run it to verify it fails**

Run: `bats system/tests/commands.bats -f 'fix lane'`
Expected: 1 failure.

- [ ] **Step 3: Write the paragraph and the sentence**

In `FOUNDRY.md` Development, after the sentence "Work follows the superpowers workflow: …", add a paragraph headed **Two lanes.** It defines a fix (clear from one sentence; no schema, no settings file, no unit template and no headless command text; one failing test that passes after the change; the gate green), says a fix ships as a pull request whose body is the issue line and the test name, says a fix may run as a Work Order whose plan is the pull request's `### Task N:` list, and states the promotion rule with "the default when in doubt is the feature lane". Everything else is a feature and follows the workflow sentence above it.

In `docs/superpowers/roadmap.md`, in the paragraph that begins "**Next, in order of value**", after "before its brainstorm.", add: "A fix, as Development in `FOUNDRY.md` defines it, skips the grill, the spec and the plan."

- [ ] **Step 4: Run the test and the gate**

Run: `bats system/tests/commands.bats -f 'fix lane'`
Expected: PASS.

Run: `system/scripts/verify_setup.sh`
Expected: exit 0, no `FAIL` in the summary.

- [ ] **Step 5: Commit**

Write `.scratch/msg-1.txt`:

```text
docs(process): the fix lane, a failing test and a pull request, no spec

A fix (clear from one sentence; no schema, settings file, unit template
or headless command text; one failing test; the gate green) skips the
grill, the spec and the plan. Everything else keeps the workflow.
FOUNDRY.md defines it; the roadmap names it; commands.bats pins both.
```

Run: `git add FOUNDRY.md docs/superpowers/roadmap.md system/tests/commands.bats`

Run: `git commit -q -F .scratch/msg-1.txt`
