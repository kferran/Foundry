# Note Tags Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/ingest` reuses a partition's existing tags, and lint keeps every frontmatter tag in one form and the system tags on their own notes (#158).

**Architecture:** A read-only `vault_index.py tags --partition P` lists frontmatter tags with counts from the index's `fields` table. `schema.tag_issues` returns two warning issues (`tag-form`, `tag-reserved`); the index stores them per note, `issues --staged` raises them to errors for notes the commit adds, and the publish gate refuses them on a note a headless run creates. `/ingest`'s prompt, `FOUNDRY.md` and the concept schema carry the rule.

**Tech Stack:** Python 3 stdlib (sqlite3 with JSON1), bats, pytest.

**Spec:** `docs/superpowers/specs/2026-10-14-note-tags-design.md`. Owner decisions on #158 (2026-10-14): open vocabulary with reuse, nested tags allowed, no new required field.

## Global Constraints

- Tag form: lowercase ASCII kebab-case `[a-z0-9]+(-[a-z0-9]+)*`, `/` allowed between segments (`project/alpha`).
- Severity: `warning` on a committed note, `error` on a staged note.
- The listing is per partition; nothing is written to `wiki/shared/`.
- Settings, `run_headless.sh` or publish-gate change: feature lane, live acceptance run before merge.
- Template rule: no hostname, user path, remote URL, employer, client, codebase or people names in any file.
- bats ruling R1: no mid-test `!`, no `&&` assertion chains, no wall-clock timing assertions.

## Rulings on the spec

- **R1 `--partition` is required.** The spec writes it optional; "never mixes partitions" is the rule, and a required flag keeps a mixed listing from existing. Cost if wrong: a default to add.
- **R2 Frontmatter tags only.** Lint and the listing read the `tags` field, not inline `#words` in a body: meeting transcripts carry `#channel` text the owner never chose as a tag. Cost if wrong: inline tags drift unchecked.
- **R3 Reserved tags by where their script writes them.** The Now page is `type: concept`, so `now` is allowed only on `wiki/<partition>/Now.md`; `rca` only on `type: rca`. `dtcc-change` is left out: no script writes it. The listing leaves reserved tags out so `/ingest` never reuses them.
- **R4 (revised after review) The hook warns; it never refuses a tag.** The spec's "error on a staged note" pictured a hand commit, but `vault_sync.sh` commits unattended through the hook, and one refused note stops the whole sync. Tag issues stay warnings everywhere in lint; the publish gate (R6) is where headless output is refused. Cost if wrong: a hand-written bad tag reaches git with a `/lint` warning.
- **R5 A digits-only tag fails the form.** Obsidian does not treat `#2026` as a tag.
- **R6 (revised after review) The publish gate refuses a tag a headless run adds.** On a created note every tag counts; on a patch, only tags the old note did not have, so an old bad tag never rejects a run. The run is rejected and its input quarantined like any other failed output. This covers research Work Orders too, whose prompt now states the form. Cost if wrong: one re-run after a bad tag.
- **R8 Tag issues only on note types whose schema has `tags`** (concept, index, rca); deprecated notes are left out of the listing.
- **R7 `INDEX_VERSION` goes to "2".** `_index_note` skips a note whose bytes are unchanged, so without a rebuild existing notes never get tag issues.

def cmd_tags(args, vault, sc):
    """Frontmatter tags in one partition with their note counts, most used first (note tags spec §3)."""
    require_vault_scope(sc)
    conn = _open(vault)
    rows = conn.execute(
        "SELECT j.value, COUNT(DISTINCT f.path) AS c FROM fields f JOIN notes n ON n.path = f.path, json_each(f.value) j"
        " WHERE f.key = 'tags' AND json_valid(f.value) AND json_type(f.value) = 'array' AND n.partition = ?"
        " GROUP BY j.value ORDER BY c DESC, j.value", (args.partition,)).fetchall()
    conn.close()
    rows = [(str(t), c) for t, c in rows if str(t) not in schemamod.RESERVED_TAGS]
    print(json.dumps([{"tag": t, "count": c} for t, c in rows]) if args.json
          else "\n".join(f"{c}\t{t}" for t, c in rows))
    return EXIT_OK

`schema.py`:

```python
TAG_FORM = re.compile(r"[a-z0-9]+(-[a-z0-9]+)*(/[a-z0-9]+(-[a-z0-9]+)*)*")
TAG_CODES = ("tag-form", "tag-reserved")


def tag_issues(rel, ntype, note, values) -> list:
    """Warnings on frontmatter tags: one form (lowercase kebab-case, / between nested parts, not digits only) and the
    system tags kept to the notes their scripts write (note tags spec §2)."""
    line, out = frontmatter.key_line(note, "tags"), []
    for tag in map(str, values):
        if not TAG_FORM.fullmatch(tag) or tag.replace("/", "").isdigit():
            out.append(Issue(rel, line, "warning", "tag-form",
                             f'tag "{tag}" is not lowercase kebab-case (a-z, 0-9 and -, / between nested parts)'))
        elif (tag == "now" and not re.fullmatch(r"wiki/[^/]+/Now\.md", rel)) or (tag == "rca" and ntype != "rca"):
            out.append(Issue(rel, line, "warning", "tag-reserved",
                             f'tag "{tag}" is a system tag, written only on {RESERVED_TAGS[tag]}'))
    return out
```
