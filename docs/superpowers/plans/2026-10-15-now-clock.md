# Now Clock Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Now lines carry two optional inline fields, `[rec:: …]` and `[due:: YYYY-MM-DD]`; `now.py add` writes a default decide-by clock and only ever tightens it; `now.py overdue` lists the lines past their clock, and the brief prints that list as **Overdue** before **From Now**.

**Architecture:** `LINE` stays as it is. One helper in `vaultlib/now.py`, `fields(statement) -> (bare, rec, due)`, strips the two fields, and every statement comparison (`add`'s dedupe, `review`'s duplicates, `meeting_prep`'s entity match) uses the bare statement. `overdue` is read-only and derives everything at read time. `brief_prep.sh` writes `overdue.md` and `clock.md`; the headless brief copies a date from `clock.md` and does no arithmetic.

**Tech Stack:** Python 3 (stdlib), bash, pytest, bats.

**Spec:** `docs/superpowers/specs/2026-10-15-now-clock-design.md` (merged in #187; the owner accepted the recommended decisions).

## Global Constraints

- Work on branch `feat/now-clock` in worktree `.scratch/clock`. Commit there; do not push or open a pull request.
- Run suites through `system/scripts/test.sh <suite.bats | pytest path> [args…]`, outside a sandbox. The gate is `system/scripts/verify_setup.sh`; the main session runs it.
- Bound tools: pytest (`test_now.py`, `test_meeting_prep.py`, `test_triage.py`, `test_rca.py`, `test_intake.py`, `test_notify.py`, `test_recall.py`), bats (`prep.bats`, `commands.bats`, `vault_integrity.bats`, `triage.bats`, `rca.bats`, `headless.bats`), the gate.
- bats ruling R1: no mid-test `!`, no `&&` assertion chains, no wall-clock timing assertions.
- No new config key, no new dependency, no new file under `system/` (so `vault_integrity.bats`'s script list is unchanged). No backfill: `seed` keeps writing clockless lines, and a repeat add without `--due` never adds a clock.
- `.claude/settings.json` is unchanged: the interactive brief reaches `now.py overdue` through `brief_prep.sh` (already allowed) and the headless brief runs no scripts.
- `brief.md` must not contain the words `carried` or `stale` (the existing From Now test).
- Template rule: no hostnames, user paths, remote URLs or names in any file.
- Commits use `git commit -F <scratchpad file>` and end with the session's `Claude-Session:` line.

## Review Focus

- A repeat add with nothing new (no `--due`, `--rec`, `--evidence`, or values equal to the line's, or a different `--evidence` on a line that has one) leaves `Now.md` byte-identical. Triage, the brief and sessions re-add every day.
- A later `--due` exits 2 before any write; an earlier one rewrites only that line, keeping its `who`, `since` and evidence.
- `overdue` counts `due < date` (a line due today is not over), merges both partitions, sorts by `due` within each group, prints every line, and writes nothing.
- The ISO date test excludes Work Order ids (`2026-10-08-export-fix`).

### Task 2: `now.py add` writes the clock and only tightens it

**Files:**
- Modify: `system/scripts/vaultlib/now.py`, `system/scripts/now.py`
- Test: `system/tests/python/test_now.py` (beside the add tests), and the exact-line assertions that go through `add` in `test_now.py` and `test_triage.py`

**Interfaces:**
- Produces: `add(vault, partition, kind, statement, today, who="", evidence="", rec="", due="") -> (status, line)`, status `added`, `exists`, `tightened` (the clock moved earlier) or `updated` (only `rec` or evidence changed); `ValueError("would loosen the clock (due <date>)")` for a later `due`. CLI: `now.py add … [--rec "<option>: <why>"] [--due YYYY-MM-DD]`, exit 2 on a loosen.
- Default clock on a new line: `since + 3` days when `who` is not empty or the bare statement holds an ISO date matching `(?<![\w-])\d{4}-\d{2}-\d{2}(?![\w-])`; otherwise `since + 30`. `--due` replaces it.

- [ ] **Step 1: Write the tests** (spec §4, §5, §11): default 3 with `who`; 3 with an ISO date in the statement; 30 with only a Work Order id; 30 otherwise; `due=` overrides; a statement holding `[due::` and a `rec` holding `]` are refused, nothing written; a repeat add with no new value leaves the file byte-identical (also on a clockless hand line, so no backfill); an earlier `due` gives `tightened` and rewrites the one line; a later one raises and the file is byte-identical, and the CLI exits 2 with `would loosen the clock`; `rec` is set then replaced; evidence is set once and a different value is `exists` with the file unchanged; the CLI prints `added: … [rec:: …] [due:: …] (…)`.
- [ ] **Step 2: Run red.** `-k "clock or tighten or loosen or rec"`. Expected: FAIL (`add` takes no `rec` or `due`).
- [ ] **Step 3: Implement.** Dedupe on `(kind, bare)`; fold the changes (`due` earlier or missing, `rec` different, evidence missing); none means `exists`; else rebuild the line with `render` from its own groups and replace it by its `rstrip()` key, then `stamp_and_prune` and write, as a new line does. The loosen check runs before any write.
- [ ] **Step 4: Run green.** Update the exact-line assertions that `add` now changes (`[due:: 2026-10-12]` with `who`, `[due:: 2026-11-08]` without, for `TODAY = 2026-10-09`). Then `test_now.py`, `test_triage.py`, `test_rca.py`, `test_intake.py`, `test_notify.py`, `test_recall.py`, `triage.bats`, `rca.bats`.
- [ ] **Step 5: Commit.** `feat(now): add writes a decide-by clock and only tightens it`.
