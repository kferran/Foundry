**Details:**
1. **Commit bypass.** The project settings pre-approve `git commit -m:*` and `git push`, and nothing denies `--no-verify`/`-n`. The pre-commit secret scan is the only gate, and the hook's own message and `vault_sync.sh` tell the reader how to skip it. A prompt-injected interactive session can commit and push a secret with no prompt.
2. **Redaction gaps.** `redact()` passes `DB_PASSWORD=…`, `API_TOKEN=…` (the `\b` fails after `_`), JSON `"password": "…"` (that pattern runs only on the telemetry path), PGP private key blocks and short `sk_live_…` keys. `secret_scan.py` misses all five. This is the path for digests, inbox drops, meeting notes and Slack notices.
3. **Work Order queue note re-screened weakly.** At each tick, `_screen` re-runs only `identifiers()`; the `hosts` and output-path checks run at add time only. A queue note edited after add (on a client, or by a synced edit) widens the research session's `allowedDomains`/WebFetch and its output path. The test run published `docs/injected.md`, `extensions/telemetry/skills/evil/SKILL.md` (an interactive session would load it) and a cross-partition note. New in the pass: `_research_dir` copies all of `wiki/<p>/`, `private/` included, into the research session's context.
4. **Symlinked folders escape publish.** The link check looks at the leaf; `is_dir` follows a symlinked folder. The test run published into `wiki/<p>/private/`, `system/agents/workcells/` and outside the vault.
5. **Notify model text.** The posting model may add up to 500 characters that skip the `_slack()` escaping (`<!channel>`, `<@U…>`, links); the checker tests length and that the notice is included. Next to #288.
6. **Headless sandbox.** `headless.settings.json` lacks `allowUnsandboxedCommands: false` and a network block, which both Work Order profiles set. The tool limits in `run_headless.sh` hold and there is no WebFetch, so the reach is small; FOUNDRY.md:317's "no network" claim is unproven.
7. **Research publish without run.lock.** The tick holds only `nightshift.lock`; a concurrent `publish.recover()` under `run.lock` can quarantine or apply the run twice.
8. **No brief, no retry.** One bad line rejects the whole publish. 10-18 has no brief (rejected: a Now line over 300 characters, written by the brief itself; #294 does not cover this writer). 10-16's 06:01 run was rejected for a target change and needed a manual rerun. Nothing retries a brief. #107 accepted this on 10-15 with "reopen on the first real occurrence"; 10-16 was that occurrence and #107 is still closed.
9. **Now page size.** 51 KB against the 25 KB mark, which only `now.py review` reads. Tracked as gap plan Task 11 (5 weekdays under 25 KB), no issue.
10. **Unit timeouts.** Intake's worst case is about 121 min against 90 (105 with the server drop-in); ingest's `flock` has no `-w`. Smoke's worst case is 46 min plus 2 per telemetry source against 35; its comment leaves out intraday's 1,020 s (1,140 after #297). Typical runs take 2.5 min; no timeout kill since 10-05. The F0 timing ratchet (`system/tests/conformance.bats`) holds both, and the units it found over at seeding, on a known-overrun list under #299.
11. **Quarantine leftovers.** By design: `quarantine.py` lists them as "resolved, safe to delete". The empty `.intake-held-*` markers are gitignored.
12. **Usage file and rca child.** `record_usage` can lose a reading between processes (atomic writes, a millisecond window, the next session rewrites it). The rca child outlives a kill by about 5 min at most.
13. **Small manifest and prep gaps.** `handoffs_site` is missing from `config_keys` (declared in the extension's own schema; extension.md:21 wrongly calls it a core key). Telemetry prep has no outer timeout; each call has its own 60 s limit.
14. **Smoke version alerts.** Once per Claude Code version change, brief only; near-daily in practice. #122 has a line.
15. **Names in the repository.** The owner closed this item as not planned in #300.
16. **#136 leftovers.** Closed with S8 (redaction, see 2), S10 (headless Read crosses partitions) and S11 (`deniedMcpServers`) untracked; S1 ruled opt-in with no revisit trigger; S9 has no ruling.
17. **Gap plan tracking.** A and C are tracked by roadmap rows. F has no issue and no row; its grill has not started.
